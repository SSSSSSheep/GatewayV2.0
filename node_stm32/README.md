# STM32 下位机

本目录包含 STM32F103ZE 下位机工程。下位机通过 USART3 与 JDY 无线模块通信，接收网关的控制帧并周期上报温度。

## 工程与构建环境

- Keil MDK / uVision 5
- ARM Compiler 5（当前工程使用 ARMCC 5.06 update 7）
- Keil STM32F1xx DFP 2.4.1
- STM32F103ZE，Cortex-M3

在 Keil 中打开 `MDK-ARM/BluetoothNode.uvprojx`，选择 `BluetoothNode` target，执行 Build。Build 成功后再连接 ST-Link，执行 Download 并复位板卡。工程引用的 HAL、CMSIS、启动文件和接口层源码均位于本目录中。

## JDY 与串口配置

固件启动时通过 USART3 发送以下配置命令：

| 配置项 | 当前值 | 用途 |
| --- | --- | --- |
| NETID | `1111` | JDY 网络 ID |
| MADDR | `0002` | 本下位机节点地址 |
| 串口 | 115200、8N1、无硬件流控 | USART3 与 JDY 模块的串口参数 |

网关地址为 `0101`。JDY 模块的 UART TX 应连接 STM32 USART3 RX（PB11），JDY UART RX 应连接 STM32 USART3 TX（PB10），并确保两端共地、电平兼容。供电及无线模块具体引脚定义应以所用 JDY 模块型号手册为准。

## 控制消息

网关下行 JSON 的 `msg` 是十六进制编码。节点 `0002` 当前支持一个字节的 ASCII 控制值：

| 十六进制消息体 | ASCII 字符 | 当前行为 |
| --- | --- | --- |
| `31` | `1` | RGB 灯开始循环显示颜色 |
| `30` | `0` | 关闭 RGB 灯并发送复位显示 |

下行目标地址为 `0002`，内部源地址及外层模块源地址应为网关 `0101`。仅收到 Broker 发布确认不能证明节点执行成功；应同时观察灯效或节点端状态。

## 温度上报

TIM6 每约 5 秒产生一次计数；累计两次后启动 DS18B20 转换，等待约 750 毫秒，再读取温度并通过 USART3 发送 JDY 帧。实际上报间隔约 10.75 秒，受主循环与传感器状态影响。

当前温度消息体为两个 ASCII 数字，例如温度整数部分 25 表示为字节 `32 35`，再由网关编码为 JSON 中的十六进制字符串 `"3235"`。此格式只保留两个数字，当前代码没有上报小数点、负号或传感器状态码。

## 屏幕诊断

| 显示 | 含义 |
| --- | --- |
| `NETID:1111` | 已执行网络 ID 配置命令 |
| `MADDR:0002` | 已执行节点地址配置命令 |
| `RUN:2A-R1` | 已执行到接收初始化之后 |
| `TEMP:CONVERT` | 最近一次启动温度转换时检测到传感器应答 |
| `TEMP:NO ECHO` | 最近一次温度转换启动时未检测到完整传感器应答 |
| `UART:TX OK` | 最近一次温度帧由 STM32 本机 UART 发送完成，不代表 JDY 或网关已收到 |
| `UART:TX FAIL` | 最近一次温度帧本机 UART 发送失败 |

温度行和发送行分别保留最近一次状态，不保证属于同一轮采集。`RUN:2A-R1` 也不证明节点此后没有发生异常。

## 联调顺序

1. 确认网关运行在 `/dev/ttyS3`、115200 8N1，并连接 Broker 的 TLS listener。
2. 复位下位机，等待屏幕显示 `RUN:2A-R1`。
3. 等待约 11 秒，检查温度行和发送行状态。
4. 向 `gateway/down` 发布目标 `0002`、消息体 `31`，确认 RGB 灯开始变化。
5. 发布消息体 `30`，确认 RGB 灯熄灭。
6. 在 Windows Broker 客户端订阅 `gateway/up`，确认收到形如 `{"conn_type":1,"id":"0002","msg":"3235"}` 的上行消息。

若灯控和温度上报同时停止，分别检查屏幕状态、网关服务日志和 RK 串口输入；MQTT PUBACK 只表示 Broker 收到了发布。
